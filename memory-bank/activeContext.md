# Active Context

## Текущее состояние

Проект уже содержит рабочую учебную реализацию MCP-сервера. README описывает установку, сборку, VS Code config, схемы трёх tools и ограничения безопасности.

Основная реализация находится в `src/index.ts`. Код компактный и читабельный, но монолитный: добавление новых tools или расширение поведения, вероятно, быстро сделает файл слишком большим.

## Что важно помнить при следующих изменениях

- Источник правды - `src/index.ts`, а не `dist/index.js`.
- После изменения TypeScript-кода нужно запускать `npm run build` или хотя бы `npm run lint`.
- Для проверки IDE-сценария нужен актуальный `dist/index.js`, потому что `.vscode/mcp.json` запускает именно его.
- Не стоит вручную редактировать `dist/index.js`; его нужно пересобирать.
- Если меняется поведение tools, нужно обновить `README.md` и при необходимости `docs/local-docs.md`.

## Текущие риски и ограничения

- В проекте нет тестов, хотя script `npm test` есть.
- В `package.json` используются зависимости со значением `latest`.
- `safe_command` не имеет таймаута, поэтому зависшая команда может надолго занять MCP-процесс.
- `project_search` делает полный обход дерева и может быть медленным на больших workspace.
- Ignore-list для `project_search` не включает все потенциально чувствительные файлы, например `.env`, хотя `.env` есть в `.gitignore`.
- Вся логика находится в одном файле, что нормально для учебного задания, но ограничивает масштабирование.

## Вероятные следующие шаги

- Добавить базовые unit tests для `parseMarkdownSections`, `globToRegExp`, `assertInsideProject` и `truncate`.
- Добавить таймаут в `safe_command`.
- Расширить ignore-list для `project_search`.
- Разнести tools и helpers по отдельным модулям, если проект будет расти.
- Закрепить версии зависимостей вместо `latest`, если нужна воспроизводимость.
